Scheduled AI search query analysis

  • Platform81
  • In production
  • Google Ads · MCP · LLM · Slack

A scheduled workflow that automates first-pass analysis of search terms across eight client accounts, recommends negative keywords with a confidence score and a suggested list placement, and puts the results in front of a person before anything changes.

  • 8client accounts covered
  • 8+ hrspreviously spent on weekly manual analysis

Problem

Search query review is one of the highest-value routine jobs in paid search and one of the least enjoyable. Every week, for every account, someone pulls the search terms report, reads through it line by line, decides which queries are irrelevant, decides whether each one should be blocked at campaign or account level, and then adds them to the right negative list.

Done properly it took me a minimum of an hour per account per week. Across eight accounts that is a full working day, every week, spent on a task that is mostly pattern recognition against context I already hold in my head about the client.

It is also the first thing to get squeezed when the week is busy, which means wasted spend accumulates quietly.

Approach

The judgement in this task is not really about the query in isolation. It is about the query against the client's context. So the workflow needed three things: reliable access to live search term data, a written form of the context I would otherwise apply from memory, and a model doing the reading.

I author a context document for each account, building it with an LLM. It sets out what the business sells and what it does not, so the analysis reads each query against the client rather than in isolation.

The analysis then runs on a schedule rather than on demand, so it happens whether or not the week is busy.

Workflow

  1. Google Ads Live search term data for the account
  2. Google Ads MCP integration Structured retrieval of the query set
  3. Client context document What the business sells, what it doesn't, known waste patterns
  4. LLM analysis Each query assessed against that context
  5. Recommendations Negative keyword, match type, confidence score, suggested list placement
  6. Slack Delivered to the account owner on a schedule
  7. Human approval A person reviews and approves before anything is applied

Human oversight

This system does not modify accounts on its own, and that is a design decision rather than a limitation I intend to remove.

Negatives are destructive in a specific way: a bad negative silently blocks traffic you wanted, and nothing in the reporting tells you it happened. The cost of a wrong exclusion is asymmetric against the cost of reviewing a list, so the AI does retrieval, analysis and recommendation, and a person does the approval, which is the part that carries the risk.

Each recommendation carries a confidence score and a suggested list placement, so a reviewer can move quickly through the clear cases and spend their attention on the ones that need it.

Impact

  • Running across eight of my client accounts.
  • Automates first-pass analysis for a recurring process that previously took 8+ hours per week. Recommendations still require approval.
  • The review happens on schedule rather than whenever there is time for it, so waste is caught earlier.

Ownership, stated plainly. I built this workflow. I did not originally build the Google Ads MCP integration underneath it. That was built by my Head of PPC. I run my own version of it through Git, modify and extend it for what my workflows need, and build on top of it.

No client data, account identifiers or employer code appear on this page. The architecture above is described at a conceptual level only.
